A fix for Bulwark instances behind a sign-in gateway, and neutral wording in the app.

The Windows installers are **not code-signed** yet, so SmartScreen will warn you on first run. Every file has a `.sha256` next to it, and a GitHub build attestation that proves it was built by this repository's release workflow.

Postern is an independent project, not affiliated with or endorsed by the Bulwark project or Stalwart Labs.

### Since v0.2.0

- fix: with a sign-in gateway in front of Bulwark (Cloudflare Access, Authelia, oauth2-proxy and the like), the window stayed blank and the gateway's login opened in the browser, where it could not finish. The login now runs inside the window. A gateway is recognised by its redirect arriving before any Bulwark page has loaded; links you follow still open in your browser
- feat: "Reset webmail session" in the tray menu clears everything the window stored (cookies, gateway sessions, local data) and starts again from the sign-in page
- change: the app's own text says "webmail" and "mail server" rather than naming Bulwark and Stalwart; the window is titled "Postern"

Known limits: a gateway that first loads a page on the webmail's own address and then redirects by script is not recognised, and an identity provider that refuses embedded browsers will refuse this window too.
